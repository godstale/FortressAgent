# Fortress 자동 평가 사용법 (Evaluation Guide)

같은 평가셋을 같은 조건으로 여러 후보(모델×설정)에 자동 실행해
품질(Q)·에이전트(A)·성능(P)·자원(R)·신뢰성(S)을 0~100 공통 척도로 비교하고,
이 PC와 작업에 가장 맞는 후보를 추천받는 기능입니다.

> 요약본은 `UserGuide.md` §8에도 있습니다. 이 문서는 전체 절차·옵션·결과 읽기를 다룹니다.

---

## 1. 시작 전 준비

1. **Ollama 실행**: 평가 후보로 쓸 모델을 미리 내려받아 둡니다.
   ```bash
   ollama run qwen2.5-coder:7b
   ollama run llama3.1:8b
   ```
2. **평가 탭 열기**: 좌측 ActivityBar의 **평가(플라스크)** 아이콘을 클릭합니다.
3. **권장 시작**: 처음이라면 작은 조합(프로파일 1개 × smoke 티어 팩 1~2개 × 후보 2개)으로 먼저 돌려 흐름을 익힙니다.

---

## 2. 평가 실행 만들기 (마법사 4단계)

평가 탭의 **[새 평가]** → 실행 마법사가 4단계로 진행됩니다.

### 2.1 단계 1 — 프로파일 (가중치·제약)

프로파일은 "무엇을 중시할지"를 정하는 기준 조합(차원 가중치 + 카테고리 가중치 + 컷라인 제약)입니다.
내장 프로파일 5종:

| 프로파일 | 용도 |
| :--- | :--- |
| **균형(balanced)** | 품질·에이전트·성능·자원·신뢰성을 고르게 비교 (기본값) |
| **코딩 에이전트(coding-agent)** | 도구 사용·코드 작성 능력 중시 |
| **한국어 문서 작성(ko-writing)** | 한국어 지식·지시 따르기·작문 중시 |
| **빠른 응답(fast-response)** | 응답 속도 중시 |
| **긴 문서 분석(long-docs)** | 긴 컨텍스트 이해·압축 후 기억 중시 |

- **[복제·편집]**으로 내장 프로파일을 복사해 가중치·제약을 바꾼 커스텀 프로파일로 저장할 수 있습니다.
- 프로파일을 바꾸면 확인 단계의 체크가 초기화되므로, 마지막에 다시 확인해야 합니다.

### 2.2 단계 2 — 평가셋(팩) 선택

- 실행할 팩을 1개 이상 고릅니다. 현재 가중치가 0인 카테고리의 팩은 흐리게 표시됩니다.
- 티어 프리셋으로 분량을 조절합니다: **Smoke-all**(빠른 맛보기) / **Standard**(표준) / **Full**(전체).
- 팩별 **에폭**(반복 횟수)·**순환(circular)**·샘플 순서 시드(기본 42)를 조정할 수 있습니다.

내장 팩 20종:

- **FAB 11종**(Fortress 전용 자작): `fab-fs-tasks`, `fab-tools-select`, `fab-tools-relevance`,
  `fab-skill`, `fab-compaction`, `fab-longctx`, `fab-viz`, `fab-code-js`, `fab-quant-probe`,
  `fab-ko-writing`, `fab-perf-probe`
- **공개셋 9종**(원본 라이선스·출처 표기): `gsm8k`, `gsm8k-perturb`, `ifeval`, `ko-ifeval`,
  `humaneval-plus`, `bfcl`, `mmlu-pro`, `kmmlu`, `kobest`

### 2.3 단계 3 — 후보·Judge·실행 옵션

- **후보**: 비교할 에이전트(모델×설정)를 1개 이상 선택합니다 (최대 24).
  목록/매트릭스 보기로 고르고, 같은 모델의 양자화 비교도 여기서 켤 수 있습니다.
- **Judge**: 루브릭·작문 계열 팩이 포함되면 Judge 설정이 필수입니다.
  외부 LLM을 Judge로 쓰려면 먼저 **설정 > 외부 연동**에서 켜고(§8) 실행 시 확인해야 합니다.
- **실행 옵션**: 결정성 모드, 신뢰성 에폭, 타임아웃 배율, 성능 반복 측정,
  후보 간 모델 언로드 여부 등을 조정합니다.

### 2.4 단계 4 — 확인 후 생성

1. 가중치·제약·기준값 전체를 화면에서 보고 수정합니다.
2. **"확인했습니다" 체크**를 해야 [실행 생성]이 활성화됩니다.
3. **[지금 시작]** 또는 **[나중에 시작]**(대기 목록에 두고 목록에서 수동 시작)을 고릅니다.
   자동·예약 실행은 없습니다.

---

## 3. 평가 중 (진행 화면)

- 같은 탭이 진행 화면으로 바뀌며 **후보×팩 매트릭스**, 실시간 미리보기(trial_delta),
  자원 차트를 보여줍니다.
- **평가 중에는 모든 채팅 입력·전송·대기열 등록이 차단**되고 상단에 배너가 표시됩니다.
  폴더 전환과 에이전트 편집도 함께 잠깁니다.
- 평가가 끝난 뒤 입력했던 내용이 **자동으로 전송되지 않으며 큐에도 남지 않습니다**.
- 중간에 앱을 종료하면 해당 실행은 `interrupted`로 표시되고, 나중에 **[이어하기]**로
  남은 Trial부터 계속할 수 있습니다.

---

## 4. 리포트 읽기

실행이 완료되면 같은 탭이 리포트로 전환됩니다.

- **추천 3종**: 최적 / 빠른 대안 / 고품질 대안을 사유 문장과 함께 제시합니다.
  신뢰구간이 겹치는 후보는 "구분 불가"로 표시됩니다.
- **순위표·차원 레이더·파레토 산점도·카테고리 히트맵**으로 강점·약점을 비교합니다.
- **실행 비교**: 같은 팩 해시를 가진 이전 실행과 후보별 점수 변화를 비교합니다
  (회귀는 ↓ 강조, 하드웨어 지문이 다르면 성능·자원 비교 차단).
- **드릴다운**: 팩 → 샘플 목록(후보별 ✓/✗/△/—) → 샘플 상세(입력, 후보별 출력,
  사고 내용, 도구 궤적, 채점기별 점수·사유, Judge 원문).
- **사람 채점**: 샘플 상세에서 직접 점수를 매기면 집계가 다시 계산됩니다.
- **경고 영역**: Judge 신뢰 낮음, 길이 편향, 자기 계열 Judge, 결정성 모드,
  샘플 수 부족(검정력) 등을 확인합니다.

---

## 5. 팩 관리·편집

평가 탭의 **팩 관리** 뷰에서 계층별 목록을 봅니다.

| 범위 | 의미 | 편집 |
| :--- | :--- | :--- |
| **내장(builtin)** | 앱 번들 20종, 읽기 전용 | [복제해서 편집]으로 개인 사본 생성 |
| **전역(user)** | 이 PC의 내 팩 | 편집·삭제 가능 |
| **[새 팩]** | 직접 작성 | 매니페스트 폼 + 샘플 표 |

- **팩 편집기**: 매니페스트(카테고리·kind·채점기·지표·tier·systemPrompt)와
  샘플 표(추가·삭제·복제·순서)를 편집하고, 저장 시 zod 검증 → 버전 patch 자동 증가.
- **[전체 검증]**으로 모든 팩의 진단을 한 번에 확인합니다 (팩별 진단·라이선스·출처 표시).

## 6. 개인 평가셋 (내 대화를 평가 케이스로)

1. 채팅 말풍선 메뉴(⋯) → **"평가 케이스로 저장"**.
2. 해당 사용자 메시지 + 직전 대화 N개(기본 4, 조정 가능)가 입력으로 변환됩니다
   (도구 결과 메시지는 요약 문자열로 치환).
3. 기준을 복수 선택: 참조 답변(현재 어시스턴트 응답 또는 직접 편집),
   결정적 체크(포함 키워드·JSON·Mermaid/Recharts 블록·정규식), 루브릭.
4. 도구를 쓴 대화라면 사용한 파일 경로 체크리스트에서 픽스처로 복사할 파일을 고릅니다
   (파일당 256KB, 합계 1MB 상한).
5. 비밀값(`.env*`, `*.pem`, `*.key`, 키·토큰 패턴 등)은 자동 제외·마스킹되며
   미리보기에서 강조 표시됩니다.
6. 저장 대상은 프로젝트 개인 팩(기본 `personal-<프로젝트폴더명>`, 없으면 자동 생성).

## 7. 가져오기·내보내기

### 7.1 가져오기 (팩 관리 뷰의 [팩 가져오기])

- **파일/붙여넣기**: Inspect JSONL, CSV(구분자·컬럼 매핑 지정), promptfoo YAML을 변환해
  전역(user) 팩으로 저장합니다. 저장 전 zod 검증과 미리보기(처음 5개 + 경고)를 거칩니다.
- **HuggingFace**: 프리셋 또는 저장소/경로/리비전/형식을 지정해 내려받아 변환합니다
  (parquet은 미지원이며 안내 메시지가 표시됩니다).
- 팩 ID 규칙을 만족해야 하며(영문 소문자·숫자·하이픈), 라이선스 ID 기본값은
  `imported-unknown`이므로 실제 출처에 맞게 고치는 것을 권장합니다.

### 7.2 내보내기 (리포트의 [내보내기]/[결과 내보내기])

- **EEE JSON**: 외부 교환 포맷(`eee-0.1-fortress` 스탬프, 모델 정보·생성 설정·
  지표 정의·신뢰구간·하드웨어 정보 포함).
- **샘플 JSONL** / **Trials CSV**: 실행 결과를 표·분석용으로 저장합니다.
- **GPQA 출처 샘플은 원문(input/output)이 제외**되고 안내 문구가 함께 기록됩니다
  (id·점수는 유지).

## 8. 외부 연동 (옵트인)

외부 LLM API·에이전트 CLI를 Judge·후보 등으로 쓰려면:

1. **설정 > 외부 연동**에서 마스터 스위치를 켭니다 (끄면 마법사에서 외부 옵션이 숨겨집니다).
2. 용도·데이터 분류별 동의를 하고, 실행마다 다시 확인합니다.
3. 모든 외부 전송은 감사 로그에 기록됩니다.

---

## 9. Arena (블라인드 선호 투표)

1. 평가 탭의 **Arena** 뷰에서 두 후보의 익명 답변을 나란히 보고 승자를 투표합니다.
2. 표가 쌓이면 **리더보드**(Bradley-Terry 순위 + 신뢰구간)가 갱신됩니다.
3. 표본이 부족하면(30표 미만) 부족 안내가 표시됩니다.
4. 내 투표 내역과 후보 쌍별 전적을 확인·삭제할 수 있습니다.

---

## 10. 자주 묻는 질문·문제 해결

- **Q. [실행 생성]이 비활성화되어 있어요.**
  A. 확인 단계의 "확인했습니다" 체크가 필요합니다. 프로파일을 다시 바꾸면
  체크가 초기화되니 마지막에 다시 확인하세요. Judge 필수 팩인데 Judge가 비어 있거나,
  외부 Judge인데 외부 확인을 안 했어도 비활성됩니다.
- **Q. 평가 중에 채팅이 안 돼요.**
  A. 정상입니다. 평가 중에는 채팅·폴더 전환·에이전트 편집이 잠기며,
  평가 종료 후 자동 해제됩니다.
- **Q. 실행이 `interrupted`로 표시돼요.**
  A. 앱 종료 등으로 중단된 것입니다. 실행 목록에서 [이어하기]로 남은 Trial부터 계속하세요.
- **Q. HumanEval+ 계열이 자꾸 skip돼요.**
  A. 해당 PC에 Python 실행 환경이 없으면 코드 실행 계열 팩은 skip됩니다.
  `fab-code-js`는 JS 런타임으로 정상 채점되니 대조용으로 돌려보세요.
- **Q. 추천이 "구분 불가"로 나와요.**
  A. 후보 간 신뢰구간이 겹친다는 뜻입니다. 에폭을 늘리거나 샘플 수를 늘려(상위 티어)
  다시 실행하면 구분력이 올라갑니다.
